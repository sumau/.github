Code Security Workflow

Same checks and sequence as the current draft (code_sec_workflow_copy), restructured for readability. Each amber marker on the diagram corresponds to a numbered note below.

What changed, and why

  1. 1
    The push boundary is explicit

    Dropping the Local / Remote lanes lost real information. The dashed divider and "runs on…" chips restore it: the pre-commit hook clearly runs on your machine, while Secret Protection runs server-side — without dedicating whole lanes to geography.

  2. 2
    One unbroken path

    The hand-off to phase 2 now exits from GitHub Secret Protection — the last gate of phase 1 — instead of dropping from the first box. The eye follows write → commit → push → checks pass → raise without backtracking.

  3. 3
    No duplicate edge labels

    "pass" appeared twice meaning two different things. Now the phase hand-off reads "checks pass" and the Actions gate reads "scans pass" — each label names its own gate.

  4. 4
    Dependabot is off the main line

    It is a scheduled watcher of the default branch, not step 8 of the pipeline. A dashed "scheduled scan" arrow makes that relationship explicit instead of implying it runs after every merge.

  5. 5
    Lane names share one grammar

    Both phases are now verb phrases — "Commit & push", "Review & merge" — so the lanes read as steps of a workflow rather than a mix of action and artifact.
